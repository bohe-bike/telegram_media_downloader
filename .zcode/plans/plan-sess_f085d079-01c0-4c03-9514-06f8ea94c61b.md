修复下载逻辑审查中发现的高优先级问题（均在 media_downloader.py / module/download_stat.py，不动整体架构）：

1. **修复重复任务计数失衡**（media_downloader.py:1017-1022）
   - worker 收到 `Downloading` 短路时，不再直接 `continue`：改为像 stop_transmission 分支一样落地计数（`finish_task += 1`），或入队前用 `_download_cache`/node 状态预检避免重复入队导致 total_task 虚增。推荐入队侧去重（add_download_task 检查该消息是否已在当前 node 的进行中队列），使 total_task 与 finalize 一一对应。

2. **消除 `except Exception: pass`**（media_downloader.py:1055-1056）
   - 记录异常日志；无论 finalize 是否成功都保证 `finish_task`/`download_status` 兜底更新，避免计数卡死。

3. **处理 `media_size` 未知的情况**（`_check_download_finish` media_downloader.py:112-122，及 :812 跳过判断）
   - 当 `media_size <= 0` 时：不删除已下载文件、不抛 DownloadSizeMismatch，直接视为成功；"已存在跳过"判断在 media_size 未知时退化为"文件存在即跳过"。

4. **配置持久化降频 + 原子写**（finalize 的 `app.update_config()`，media_downloader.py:658；module/app.py:935-944）
   - `update_config` 改为：写文件前先写 `.tmp` 再 `os.replace`（原子替换）；finalize 中不再每次落盘，改为标记 dirty + 定时（如每 30s）或在退出/任务批次结束时统一落盘。

5. **附带小修**（同一次改动顺带完成）：
   - 重试等待后若 `app.is_running` 为 False，调 `finish_download_status` 落地 UI 记录，避免卡在 "retrying"（media_downloader.py:697-705）。
   - 显式捕获 `asyncio.TimeoutError`（media_downloader.py:917）。
   - 修正 "FlowWait" 日志拼写（media_downloader.py:913）。

6. **补充/更新单元测试**（tests/test_media_downloader.py、tests/test_common.py 已有相关测试可扩展）：
   - 重复入队后计数守恒的用例；
   - media_size=0 时下载成功不删文件的用例；
   - update_config 原子写/降频的用例。

不改动的部分（有意保留）：`save_msg_to_file` 的路径拼接、`download_status` 字典内存增长、`record_download_status` 的 Cache 淘汰——影响小或需要更大重构，可在后续迭代处理。
